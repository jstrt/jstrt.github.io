# HTTP와 HTTPS 개념과 차이점

## 1. HTTP란 (HyperText Transfer Protocol)

HTTP는 WWW(World Wide Web) 상에서 클라이언트와 서버 간에 데이터를 주고받기 위한 **TCP/IP 통신 프로토콜**입니다.  
HTTP는 클라이언트와 서버 간의 **요청(Request)**과 **응답(Response)** 구조로 동작합니다.

### HTTP의 특징

**1. Stateless(무상태)**  
HTTP는 상태를 유지하지 않는 프로토콜입니다.  
각각의 요청은 독립적으로 처리되며, 이전 요청의 상태를 기억하지 않습니다.

**2. Connectionless(비연결성)**  
요청과 응답이 한 번 이루어지면 연결이 종료됩니다.  
각 요청은 독립적으로 처리되므로 연결을 지속적으로 유지할 필요가 없습니다.

**3. Request-Response 모델**  
클라이언트가 요청(Request)을 보내면 서버는 응답(Response)을 반환하는 구조를 따릅니다.  
GET, POST, PUT, DELETE 등의 HTTP 메서드를 사용하여 서버에 동작을 요청하며,  
서버는 상태 코드와 함께 데이터를 응답으로 반환합니다.

**4. URI (Uniform Resource Identifier)**  
HTTP는 리소스를 식별하기 위해 URI를 사용합니다.  
URI는 URL(Uniform Resource Locator)을 포함하는 개념으로,  
클라이언트는 URI를 통해 요청할 리소스를 지정합니다.

### HTTP의 단점

HTTP는 데이터를 **평문(Text)**으로 전송하기 때문에 보안에 취약합니다.  
중간에서 패킷을 가로채면 데이터 내용을 확인하거나 변조할 수 있어  
도청 및 위·변조의 위험이 존재합니다.

---

## 2. HTTPS란 (HyperText Transfer Protocol Secure)

HTTPS는 HTTP에 **보안 기능을 추가한 프로토콜**입니다.  
클라이언트와 서버 간의 데이터 전송을 안전하게 보호하기 위해  
**SSL/TLS 프로토콜**을 사용합니다.

HTTPS는 **대칭키 암호화와 공개키 암호화 방식을 조합**하여  
데이터를 암호화하고 안전한 통신을 제공합니다.

---

## SSL과 TLS란?

**SSL(Secure Sockets Layer)**은 웹 초기 보안 프로토콜로,  
데이터의 기밀성과 무결성을 보호하기 위해 사용되었습니다.  
하지만 여러 취약점이 발견되면서 현재는 더 안전한 TLS로 대체되었습니다.

**TLS(Transport Layer Security)**는 SSL의 후속 프로토콜로,  
보다 강력한 암호화 알고리즘을 제공하며  
데이터 기밀성, 무결성, 서버 인증을 보장합니다.

---

## HTTPS의 암호화 방식

HTTPS는 SSL/TLS 프로토콜을 사용하여 데이터를 암호화합니다.  
통신이 시작되기 전에 클라이언트와 서버는 **핸드셰이크 과정**을 통해  
암호화에 사용할 키를 교환합니다.

이 과정에서 **공개키 암호화 방식**을 사용해 안전하게 키를 전달하고,  
이후 실제 데이터 통신은 효율적인 **대칭키 암호화 방식**으로 이루어집니다.

따라서 중간에서 데이터를 탈취하더라도  
암호화된 내용을 해독할 수 없습니다.

---

## 3. 왜 HTTPS인가

HTTPS는 웹 사이트 보안을 위해 가장 기본적이면서도 중요한 기술입니다.  
사용자의 개인정보를 보호하고, 다양한 사이버 공격으로부터  
웹 서비스를 안전하게 유지할 수 있습니다.

HTTPS는 데이터 암호화뿐 아니라  
클라이언트와 서버 간의 **인증 과정**을 통해 보안을 강화합니다.  
이로 인해 사용자는 더 안전한 웹 환경을 제공받고,  
웹 사이트의 신뢰도 또한 높아집니다.

또한 HTTPS는 **SEO(Search Engine Optimization)** 측면에서도 중요합니다.  
구글을 비롯한 주요 검색 엔진은 HTTPS를 사용하는 웹 사이트를  
더 신뢰하고 검색 결과에서 우선적으로 평가합니다.

HTTPS의 실제 사용 예시
-로그인·회원 인증 및 결제·금융 서비스에서는  
아이디, 비밀번호, 결제 정보 같은 민감한 데이터가 전송되므로,  
HTTPS를 통해 데이터를 암호화하지 않으면 정보 탈취 및 금전적 피해가 발생할 수 있습니다.
-공공 와이파이 환경에서는 네트워크 트래픽이 쉽게 도청될 수 있기 때문에,  
HTTPS를 사용하지 않으면 중간자 공격(MITM)에 의해 개인정보와 세션이 노출될 위험이 크다.

---

## 4. 결론

HTTP와 HTTPS의 개념과 차이점을 살펴보았습니다.  
HTTPS는 웹 사이트 보안을 강화하고  
사용자의 신뢰를 얻기 위해 필수적인 요소입니다.

데이터 암호화, 사용자 인증, 데이터 무결성 보장을 통해  
안전한 웹 환경을 제공하며  
웹 사이트의 가치와 신뢰도를 높이는 중요한 기반 기술입니다.
