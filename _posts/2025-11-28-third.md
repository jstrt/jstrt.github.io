<h2>1. XSS (Cross-Site Scripting, 크로스 사이트 스크립팅)</h2>
<p>
XSS는 웹 애플리케이션에서 많이 나타나는 취약점의 하나로,
웹사이트 관리자가 아닌 공격자(attacker)가 웹 페이지에 악성 스크립트를
삽입할 수 있는 취약점입니다.
이름이 CSS가 아닌 이유는 웹 기술인 CSS와 헷갈릴 수 있기 때문입니다.
</p>

<p>
이 취약점은 클라이언트로부터 입력받은 값을 제대로 검사하지 않고 사용할 경우 발생하며,
해커가 사용자의 정보(쿠키, 세션 등)를 탈취하거나,
자동으로 비정상적인 기능을 수행하게 만들 수 있습니다.
주로 다른 웹사이트와 정보를 교환하는 방식으로 동작하므로
사이트 간 스크립팅(Cross-Site Scripting)이라고 합니다.
</p>

<hr>

<h2>2. XSS의 공격 유형</h2>
<p>
XSS의 공격 유형은 표준으로 명확하게 정의되어 있지는 않지만,
오늘은 XSS를 대표하는 3가지 유형을 다루겠습니다.
</p>

<h3>1) Reflected XSS</h3>
<p>
반사형 공격이라고 불리는 Reflected XSS를 쉽게 설명하면 다음과 같습니다.
</p>

<blockquote>
해커가 악성 스크립트가 포함된 링크를 이메일이나 메신저로 전송하고,
사용자가 해당 링크를 클릭하면 서버가 해당 입력 값을 그대로 응답에 반사하여 전달하면서
악성 스크립트가 사용자의 브라우저에서 즉시 실행되는 공격입니다.
</blockquote>

<p>
사용자가 특정 파라미터에 입력한 값을 서버가 응답으로 그대로 반사하여 보내줄 때 발생하며,
서버에 스크립트를 저장하지 않기 때문에 서버의 필터링을 우회할 수 있습니다.
</p>

<h4>특징</h4>
<ul>
  <li>URL을 만들어 특정 사용자가 클릭하도록 유도하는 방식</li>
  <li>URL 파라미터 데이터가 서버 응답에 그대로 삽입되는 경우 발생</li>
  <li>요청과 응답 페이지가 동일해야 함</li>
  <li>주로 GET 방식에서 발생</li>
</ul>

<hr>

<h3>2) Stored XSS</h3>
<p>
저장형 공격이라고 불리는 Stored XSS는 다음과 같이 설명할 수 있습니다.
</p>

<blockquote>
해커가 악성 스크립트를 웹사이트의 게시판, 댓글,
또는 사용자 프로필과 같이 서버에 저장되는 영역에 삽입하는 공격입니다.
이후 다른 사용자들이 해당 페이지를 조회할 때
저장된 악성 스크립트가 자동으로 실행됩니다.
</blockquote>

<h4>특징</h4>
<ul>
  <li>서버 필터링으로 우회가 어렵지만 성공 시 피해 범위가 매우 큼</li>
  <li>데이터가 저장되고 출력되는 위치가 서로 달라도 무관</li>
  <li>모든 방문자를 대상으로 공격이 가능하여 매우 위험함</li>
</ul>

<hr>

<h3>3) DOM Based XSS</h3>
<p>
DOM(Document Object Model) 기반 공격이라고 불리는 DOM Based XSS는
서버가 아닌 클라이언트에서 발생하는 XSS 공격입니다.
</p>

<blockquote>
해커가 악성 스크립트를 URL, 입력값 또는 브라우저가 참조하는 데이터에 삽입하고,
웹페이지에 포함된 JavaScript가 해당 데이터를 검증 없이 DOM에 삽입하면서
브라우저 내부에서 악성 스크립트가 실행되는 공격입니다.
</blockquote>

<p>
서버의 응답은 정상적이지만,
클라이언트 측 JavaScript 처리 과정에서 문제가 발생하며,
사용자가 특정 URL에 접근하거나 페이지를 로드하는 순간
악성 스크립트가 브라우저 내부에서 자동으로 실행됩니다.
</p>

<h4>특징</h4>
<ul>
  <li>악성 스크립트가 서버에 저장되지 않음</li>
  <li>브라우저의 JavaScript 처리 과정에서 발생</li>
  <li>서버 로그에 남지 않는 경우가 많음</li>
  <li>location.href, location.hash, document.URL 등을 통해 발생</li>
</ul>

<hr>

<h2>3. XSS 공격 대응</h2>

<h3>1) 입력 값 검증 (Input Validation)</h3>
<ul>
  <li>입력 데이터의 길이 제한</li>
  <li>&lt;script&gt;, &lt;iframe&gt;, onerror, onclick 등 스크립트 실행 가능 문자열 필터링</li>
  <li>숫자, 영어, 특정 문자 등 허용된 형식만 입력 허용</li>
  <li>화이트리스트 방식이 가장 안전한 방법</li>
</ul>

<h3>2) 출력 시 HTML 이스케이프 처리 (Output Encoding)</h3>
<p>
입력 값 자체를 완벽히 차단하지 못하더라도,
출력 시점에 스크립트로 해석되지 않도록 처리해야 합니다.
</p>

<ul>
  <li>&lt; → &amp;lt;</li>
  <li>&gt; → &amp;gt;</li>
  <li>" → &amp;quot;</li>
</ul>

<h3>3) JavaScript에서 innerHTML 사용 지양</h3>
<p>
검증되지 않은 데이터를 DOM에 직접 삽입하는 것은
DOM Based XSS의 주요 원인입니다.
</p>

<pre><code>// 위험한 방식
element.innerHTML = userInput;

// 안전한 방식
element.innerText = userInput;
element.textContent = userInput;
</code></pre>

<h3>4) HttpOnly 쿠키 옵션 설정</h3>
<p>
HttpOnly 옵션이 설정된 쿠키는 JavaScript에서 접근할 수 없기 때문에
XSS 공격을 통한 쿠키 탈취를 방지할 수 있습니다.
</p>

<h3>5) CSP (Content Security Policy) 적용</h3>
<p>
CSP는 브라우저가 인라인 스크립트나 외부 스크립트의 실행을 제한하도록 설정하는 보안 정책입니다.
</p>

<ul>
  <li>인라인 스크립트 실행 차단</li>
  <li>허용된 출처의 스크립트만 실행 가능</li>
</ul>

<h3>6) 최신 라이브러리 및 프레임워크 사용</h3>
<p>
최신 웹 프레임워크들은 기본적으로 XSS 방어 기능을 포함하고 있으며,
보안 패치 및 업데이트는 필수입니다.
</p>
